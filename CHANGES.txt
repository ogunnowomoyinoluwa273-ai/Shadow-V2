SHADOW - ALL FIXES IN ONE ZIP (supersedes shadow-speedup, shadow-memory-fix and shadow-dm-fix)

INSTALL: stop Shadow, copy these files over your project (same folders), keep your own .env
(only .env.example is included; no session or data files). Then npm start.
The separate shadow-deploy-kit.zip (hosting files) is unaffected - add it on top if you use it.

PHASE: NATURAL-LANGUAGE COMMANDS ("Shadow, tag everyone in this group" runs .tagall)
  - New src/services/nlCommands.js decides WHICH registered command a request means and with which arguments; it never runs
    anything itself. The message handler turns the decision into the equivalent dot-command and sends it through the same
    dispatcher as typed commands, so owner / sudo / admin / bot-admin / group-only / disabled-command checks are unchanged.
  - All 84 commands in .menu have natural phrasing; commands added later are reachable by name/alias automatically (and are
    treated as sensitive if group-only or owner-only).
  - Sensitive actions (kick, promote, demote, mute, tagall, group settings, delete, broadcast ...) are not run on the first
    request: Shadow asks you to reply "Shadow, yes" within 2 minutes (or "Shadow, cancel"). Only the requester can confirm,
    and the action runs with the original message so tags and replies still apply. Typed dot-commands never ask.
  - Missing information (who? which city? on or off?) is asked for; unclear or conversational requests still go to the AI.
  - Turn off with NATURAL_COMMANDS=off in .env. Dot-commands and .menu are untouched.

NEWEST - slow "loading" after a restart (offline backlog)
  - Cause: after being offline, WhatsApp sends everything missed (about a day of group chatter). Shadow processed
    each old message like a new one: it rewrote its history file once per message (some writes took over a second)
    and could even act on old commands / "Shadow ..." messages.
  - Fix: messages older than MAX_MESSAGE_AGE_SECONDS (default 300 = 5 minutes) are treated as history: no commands,
    no AI, no moderation. If they are newer than the chat-context window (3 hours) they are still kept as context;
    older ones are skipped without touching the disk. One log line summarises what was skipped.
  - MAX_MESSAGE_AGE_SECONDS=0 turns the guard off. If your PC clock is more than ~5 minutes AHEAD of real time,
    Shadow would skip live messages as "old": keep Windows time sync on, or raise/disable the setting.

NEWEST - recognition mark on Shadow's messages
  - Shadow runs on your own WhatsApp account, so his replies looked exactly like your messages. Every message he
    sends (replies, commands, stickers, media) now gets a spade reaction from the same account. Your own typed
    messages never get it. The reaction is sent in the background, so replies are not slowed down.
  - Change or turn off with BOT_MESSAGE_REACTION in .env (empty = off, or any other emoji). Default is the spade.
  - The short-lived spade Shadow puts on YOUR message while he is thinking is separate and unchanged.

NEW IN THIS UPDATE - wrong command run for ordinary requests
  - Bug: asking "give me the lyrics for ..." answered "Usage: .aimodel(status)". Any request starting with
    give/tell/find/show gave the AI a tool that can run ANY command; with no lyrics command it picked the
    nearest-looking one and Shadow repeated that command's usage error.
  - Fix 1: the command tool is only offered when the request actually relates to a command (its name,
    a word inside its name such as "description" in setdescription, or a meaningful word from its description).
  - Fix 2: even when offered, a command the request is not about is refused (pending confirmations exempt).
  - Side effect: ordinary questions no longer take the slower tool-enabled model path, so they answer faster.
  - Shadow has no lyrics lookup; such questions now go to the AI model like any other question.

EARLIER (all included)
  - Speed: history writes no longer block the model request or the reply.
  - Memory: 14-day history, per-person keys that survive re-linking, group earlier-exchanges, better memory recall,
    one-time lossless data merge with .bak backups (4 optional settings in .env.example).
  - DMs: owner/sudo recognised under every identity form (phone number or LID); .delete/.clear work in DMs.
